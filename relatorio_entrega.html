2. Fluxo Cliente-Servidor e Arquitetura em Camadas

Fluxo Unidirecional Obrigatório:
Cliente -> Controller -> Service -> Repository -> Banco de Dados (PostgreSQL)
  • Cliente: Envia a requisição HTTP (Request) contendo o método (GET, POST, PUT, DELETE) e corpo JSON quando aplicável.
  • CursoController: Responsável apenas pelo protocolo HTTP. Recebe os dados via anotações Spring (@RequestBody, @PathVariable), delega a chamada para o serviço e retorna ResponseEntity com o status correto. O Controller não acessa o banco nem a camada de dados diretamente.
  • CursoService: Concentra exclusivamente a inteligência do negócio e as validações (nome não nulo nem em branco, carga horária maior que zero). Se inválido, rejeita a operação com 400 Bad Request. Se válido, aciona o repositório.
  • CursoRepository: Interface que estende JpaRepository<Curso, Long>, delegando ao Spring Data JPA a geração transparente das consultas SQL contra o banco de dados.
  • PostgreSQL: SGBD relacional que assegura a persistência definitiva dos dados em disco.

3. Contrato da API REST (Endpoints Obrigatórios)

Método Endpoint Operação Payload Enviado (Body) Resposta e Status HTTP
GET /cursos Listar todos os cursos Nenhum 200 OK — Lista JSON com os cursos cadastrados
GET /cursos/{id} Buscar curso por ID Nenhum 200 OK (se encontrado) ou 404 Not Found
POST /cursos Cadastrar curso {"nome": "Back-End Frameworks", "cargaHoraria": 60} 201 Created — Objeto criado com ID gerado pelo banco
PUT /cursos/{id} Atualizar curso {"nome": "Back-End Avançado", "cargaHoraria": 80} 200 OK (atualizado) ou 404 Not Found
DELETE /cursos/{id} Remover curso Nenhum 204 No Content (removido) ou 404 Not Found

4. Configuração da Conexão com o PostgreSQL

Configuração aplicada em src/main/resources/application.properties:

spring.application.name=api-cursos
server.port=8080

spring.datasource.url=jdbc:postgresql://localhost:5432/api_cursos
spring.datasource.username=postgres
spring.datasource.password=postgres
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true

7. Checklist Final de Avaliação

  • ✓ Existem exatamente cinco endpoints principais de CRUD: GET /cursos, GET /cursos/{id}, POST /cursos, PUT /cursos/{id} e DELETE /cursos/{id}.
  • ✓ O Controller trata apenas questões HTTP: Delega toda a lógica para o CursoService e devolve ResponseEntity com códigos de status HTTP corretos.
  • ✓ O Service contém as regras de negócio: Validações de nome obrigatório (não nulo nem em branco) e cargaHoraria > 0 antes de acionar a camada de dados.
  • ✓ O Repository realiza o acesso aos dados: O Controller não conhece o Repository; a comunicação de persistência ocorre estritamente via Spring Data JPA.
  • ✓ Curso está anotado como entidade JPA: Anotações @Entity, @Table(name = "cursos"), @Id e @GeneratedValue(strategy = IDENTITY).
  • ✓ O projeto usa PostgreSQL: Conexão ativa com banco de dados PostgreSQL relacional (api_cursos).
  • ✓ Os status HTTP estão adequados às operações: 200 OK, 201 Created, 204 No Content, 404 Not Found e 400 Bad Request.
  • ✓ Os testes foram documentados: README.md, relatórios, coleção Postman e arquivo de requisições HTTP.
  • ✓ Os dados permanecem depois do reinício: Persistência comprovada e demonstrada na Atividade 15.
